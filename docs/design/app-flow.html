MassOrca app flow

How a person moves through the desktop app and the Android companion, screen by screen. Each box is a screen from the screen inventory. The step tables, gaps and assumptions are in app-flow.md (plain text).

  • Solid boxes are screens. Arrows show the next step.
  • Dashed boxes are branches: an error, an empty state, an offline host, or a choice the owner has not made yet.
  • G and A numbers match the gaps and assumptions in app-flow.md.

Desktop journeys fill the top four rows: J13 is in the third row, and J14 stands alone in the fourth. The Android companion is the lane at the bottom, and it pairs with a host through J2.

Journeys, one diagram each

Each diagram is the main path of its table in app-flow.md. Dashed boxes are the branches that table names.

J1 First launch and setup (desktop)

A working desktop: local service running, agent accounts carried over, a theme chosen, session import optional.

J2 Add a remote host and pair it

A server or SSH host appears in the sidebar as a connected host, with its workspaces listed.

J3 Create a workspace

A new workspace exists under a project, optional setup has run, and the start page opens on it.

J4 Run an agent in a workspace

A session runs in a workspace. The owner watches it, answers approvals, then finishes, continues or resumes it.

J5 Terminals: open, split, survive

Terminals keep running when the window closes, and they come back in their layout.

J6 Review diffs and source control

The owner reviews agent changes, comments, stages and commits, then checks CI or opens a PR.

J7 Browser pane: dev server preview

A dev server opens in the browser pane. The owner clicks through it and can hand an element to the agent.

J8 Settings and keybindings

The owner finds a setting, changes it, and reassigns a shortcut without leaving a conflict.

J9 Import a session from another tool

A session from another agent tool continues in MassOrca.

J10 Install an extension

The owner installs an extension, grants what it asks for, enables it, and sees its panel appear.

J11 Build my own extension

The owner builds an extension from a template, runs it, iterates on the code, then disables or removes it.

J12 Android companion

From a fresh install, the phone pairs, follows a session, approves a request, uses the terminal, and recovers after a disconnect.

J13 Bot Teams: switch mode, talk to a team, track work

The owner switches the rail to Bot Teams, talks to a team in its Conference room, follows the tasks on its Board, schedules routines, and checks them on the calendar.

J14 Give an agent a secret

The owner gives an agent a credential without pasting it into the chat, from the desktop or the phone. The value is stored on the host and reaches the agent only at run time.

Desktop layout

The Activity rail, the Sidebar and the Title bar read as one Frame, filled with the same frame colour and with no seam between them. The Canvas is inset in that frame, with a rounded top-left corner. Inside it, left to right, sit the Conversation, the Session summary, the Work panel and the Project sidebar. The Status bar runs along the bottom of the Canvas. The rail stays visible when the Sidebar is hidden, and with the Sidebar hidden the Canvas corner sits right next to the rail. Tasks, Calendar, Marketplace, Settings, Automations and the Bot Teams pages open as full pages over the canvas, with the Sidebar hidden; Back returns to the session. The Title bar is a band across the top of the frame, with the sidebar toggle, back and forward, the session title, region toggles and window controls (on the right on Windows and Linux, at the left on macOS). Titlebar tabs stay dropped. From any other page, the mode switch first returns to the current mode's home; a press at home switches the mode. These two points were decided on the owner's behalf (pending-owner-review.md, items 13 and 14).
