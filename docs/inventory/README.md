# Functional inventory of the current MassOrca app

Status: draft for owner review, 2026-11-12 (updated overnight).

**Reference described: pv96**, commit `d3c6311a531` on branch `custom/pv27-unified`, which is `custom/integration` (`f23a48ca8ca`) plus 852 commits not yet merged there. The inventory was first written from `custom/integration`; a delta pass then updated every domain to pv96. Rows changed or added by that pass say `pv96 (unmerged)` in the Source column, and the matching sections in the domain documents carry a "Source: pv96 (unmerged)" line. Nothing after pv96 (branch `claude/keep-main-pv97`) is described.

**Start here:** [first-version.md](first-version.md) is the short list the owner validates first. [open-questions.md](open-questions.md) lists the decisions, the ones that block the first-version scope at the top.

This folder describes what the current MassOrca app does, by observable
behaviour, so the owner can choose the first-version scope of the Rust rebuild
(see [../PLAN.md](../PLAN.md), Phase 0). It describes behaviour and rules, not
code, and it does not prescribe the Rust design. Screens and visual design are
covered separately in `docs/design/`.

Every mark in the summary table is a **proposal**. The owner decides.

## How this was produced

The reference source (a read-only checkout of the current app) was read by one
worker per domain, using file search and reading only; nothing was built or
run, and no feature was tried in the running app. Each domain document lists
the directories it read and what it did **not** read or holds with low
confidence. In short, the following were not read in depth anywhere:

- For pv96, each domain worker read that domain's diff against
  `custom/integration` and the feature and QA documents in `odd/tasks/` on the
  pv96 commit. Renderer and mobile code was read only to learn behaviour.
- `src/renderer` and `mobile` (UI detail belongs to `docs/design/`; they were
  only searched to learn what the UIs ask the core to do).
- Test files (about 13,000), except where a test name clarified a rule.
- The largest internal modules were sampled rather than read in full: the RPC
  runtime (`src/main/runtime`, ~178k lines), Electron IPC (`src/main/ipc`,
  ~87k lines), most of `src/main/browser`, most of the ~200 `orcad` modules,
  relay internals, and the native computer-use helpers.
- Services outside this repository: the account/login backend, the skill
  sharing API and feedback intake (they live in a private repository or on the
  vendor's site), and external tools the app drives (`agent-browser`,
  `serve-sim`, `sherpa-onnx`, vendor agent CLIs). Their behaviour is inferred
  from the calling code.
- Claims marked "inferred", "reported" or "UNVERIFIED" in the domain documents
  were not confirmed.

## Domains

**Workspaces and worktrees** ([workspaces.md](workspaces.md), WS). Adding
repositories and plain folders, creating, renaming, archiving and removing
workspaces as git worktrees or folders, branch naming, setup scripts, project
groups and profiles. Identity is host-qualified: the same path on two hosts is
two projects. Windows diverges most (junctions, case-insensitive paths, WSL
UNC aliases).

**Terminals** ([terminals.md](terminals.md), TERM). PTY sessions in a
workspace, the detached per-user terminal host that keeps them alive across UI
restarts and app updates, attach/detach, scrollback and replay, shell
detection and shell integration per OS, ConPTY and PowerShell specifics,
terminal themes. A host crash or reboot still ends running terminals.

**Git and source control** ([git.md](git.md), GIT). Status, diffs against the
working tree, index and base branch, staging, commits with AI-generated
messages, branches, push/pull/fetch, conflict detection, worktree-level git
operations, all through the user's git binary with no credential prompts.
Stash, blame, amend, interactive rebase and hunk staging do not exist today.

**Hosting providers and issue trackers** ([providers-and-trackers.md](providers-and-trackers.md), SCM).
GitHub (the largest), GitLab, Bitbucket, Azure DevOps and Gitea pull or merge
requests, checks and comments, plus Jira and Linear issues, creating
workspaces from issues and PRs. No provider submits a review verdict.

**Agent integrations** ([agents.md](agents.md), AG). The catalog of 45 agent
ids, detection and version probing, launching agents in terminals, prompt
delivery (six injection modes), permission presets (bypass is the shipped
default), workspace trust pre-writes, resume, structured chat for 7 agents
(off by default, local only), ACP, delegated child sessions and AI text
generation through agent CLIs.

**Agent status and hooks** ([agent-status.md](agent-status.md), STAT). The
four-state status model (working, blocked, waiting, done), hooks written into
each agent's own config, the status store on the execution host, unread and
attention markers, notifications and sounds, keep-awake, and behaviour when a
remote host disconnects.

**Accounts, credentials and usage** ([accounts-and-usage.md](accounts-and-usage.md), ACC).
Signing in to Claude Code and Codex, multiple accounts per agent and switching
between them, token refresh ownership, read-only detection for other agents,
usage and rate-limit reading, credential protection, and carrying existing
subscriptions into the new core (an explicit requirement).

**Session history** ([session-history.md](session-history.md), HIST).
Discovering past sessions of 24 agents from their own files on disk, titles
and previews, full-text search (off by default), the transcript viewer,
resuming in a terminal, adopting into a structured chat, and importing
sessions from other tools (an explicit new requirement; nothing imports today).

**SSH and remote hosts** ([remote-hosts.md](remote-hosts.md), REM). Adding SSH
hosts, the managed server deployed on each host with the relay as fallback,
what runs remotely, reconnect rules ("losing contact is not proof a process
died"), port detection and forwarding, WSL as a local path variant, and
recipe-based ephemeral VMs.

**Headless server and pairing** ([server-and-pairing.md](server-and-pairing.md), SRV).
Running headless, the network listener, pairing phones and desktops with QR
codes and tokens, end-to-end encryption, multiple clients, version
negotiation, reconnect and resync. TLS code exists but is not wired in.

**Automations, bot teams and orchestration** ([automations.md](automations.md), AUTO).
Scheduled and triggered automations (desktop scheduling runs only while the app
is open), bot teams, the orchestration commands agents call, and artifacts
published to the cloud. Two orchestration generations coexist. Owner direction
(2026-11-12): orchestration and delegation are in the first version as one
engine for both modes, and Routines and Automations are one schedule engine
with two presentations. New features: Routines, web address triggers, the
Calendar, team files and memory (AUTO-28 to AUTO-31).

**Bot Teams** ([bot-teams.md](bot-teams.md)). A core mode of the product by
owner decision (2026-11-12), switched from the activity rail: teams of bots, a
Conference room that turns stated requirements into tasks on the team's Board,
delegation by the lead bot, Routines, Files and Memory. Its features keep their
`AUTO` IDs; the guide lists them and shows how the owner's direction differs
from the incomplete bot teams in the current app.

**Browser pane and devices** ([browser-and-devices.md](browser-and-devices.md), BRW).
The integrated browser (tabs, navigation, localhost preview, devtools,
profiles, screenshots), agent browser automation (about 80 CLI commands),
desktop computer use on three OSes, the Android emulator, voice input. Lists
what the pane needs from a web engine.

**Skills, plugins and marketplace** ([skills-and-plugins.md](skills-and-plugins.md), SKL).
Installing and sharing skills across agents, bundled guides, the marketplace,
and the plugin system (off by default, full-access worker).

**Command-line interface** ([cli.md](cli.md), CLI). 251 command paths in 32
groups: installation on PATH per OS, connecting to the app or a server, and
the command groups people and agents use. Owner-only commands are refused over
the SSH relay.

**Cloud services** ([cloud.md](cloud.md), CLD). The mobile relay and the push
gateway in this repository; accounts, login and skill sharing live elsewhere.
Telemetry goes to a third-party analytics service.

**Desktop app platform** ([app-platform.md](app-platform.md), PLAT).
Installable builds per OS, auto-update channels, single instance, startup
preflight checks, windows, tray, dock and menus, crash reporting, opt-in
telemetry, diagnostics bundles, safe quit and durable writes.

**Settings, persistence and files** ([settings-and-files.md](settings-and-files.md), SET).
The settings model, per-profile SQLite state, schema versions and backups,
sealed secrets, keybindings (91 actions), file explorer and file operations,
the built-in editor, quick open and text search, external editors, and import
of the Electron profile.

**Customisation and extensibility** ([customisation.md](customisation.md), CUS).
Cross-cutting view of every customisation surface (`orca.yaml`, agent
overrides, agent-state rules, quick commands, themes, hooks, skills, plugins),
the existing DeepSeek Harness integration, a research note on the DeepSeek
Harness plugin model, and options for our own extension model. Customisation
is a design principle of the rebuild (see PLAN.md). pv96 adds custom
Marketplace items, marked instruction sections and MCP entries written into
agent configs (CUS-09 to CUS-11).

**Prototypes and design system** ([prototypes.md](prototypes.md), PROTO). New
domain from the pv96 pass: asking an agent for design directions from a chat,
the Prototypes list and viewer, annotating and iterating, merging directions,
and a project design system. Prototypes is core with a Workspaces Sidebar entry
(decided on the owner's behalf, pending review), so the request, list and
viewer are proposed for the first version.

## Reading the proposal

- **The first-version proposal is still large.** 190 of 542 features are
  proposed for the first version (49 S, 96 M, 42 L, 3 XL). Each domain worker
  proposed in isolation, so the total has not yet been cut to a coherent
  minimum. How it grew: 137 of 455 from the first pass on `custom/integration`;
  168 of 461 after the owner's design decisions of 2026-11-12 (Bot Teams as a
  core mode, orchestration, one schedule engine, model picker, usage rings,
  Tasks page, secret vault, light and dark themes; those rows say "Owner
  direction"); 181 of 541 after the pv96 delta; 190 after prototypes became
  core overnight and a consistency pass against the owner's decisions moved
  CLI-14, CLI-23, CLI-32, WS-41 and SKL-27 in. The three XL items are the structured chat platform (AG-15),
  the Claude chat adapter (AG-17) and the Conference room (AUTO-13). Start
  with [first-version.md](first-version.md) and the blocking decisions at the
  top of [open-questions.md](open-questions.md).
- **Owner decisions win.** Where pv96 behaves differently from an owner
  decision (for example, pv96 routes room requests without a lead bot and runs
  routines on their own scheduler), the row keeps the owner's direction and the
  difference is an open question. Decisions marked "on the owner's behalf,
  pending review" in `docs/design/pending-owner-review.md` are treated as
  decided, and say so where they change a mark.
- **Explicit requirements are reflected:** subscription migration (ACC-24,
  SET-08), session import (HIST-18), browser pane (BRW-01, BRW-02, BRW-07), and
  customisation as a design principle (CUS-08 and the extension column).
- **Known overlaps between domains:** per-agent command, arguments and
  environment appear as AG-11 and CUS-04; theme import (SET-28) and plugin
  themes (CUS-06); agent-driven text generation (AG-27) and AI commit messages
  (GIT-10); delegated sessions (AG-26 and AUTO-20, one delegation engine by owner decision; usage-headroom routing ACC-26 stays later); bringing a child's work back into the parent (AUTO-32, GIT-30, AG-31); the checklist card (AG-32, WS-36);
  orchestration CLI commands (CLI) and orchestration (AUTO). Count each once
  when sizing.
- **Sizes** (S = days, M = 1-2 weeks, L = several weeks, XL = months) are rough
  estimates for reimplementing the behaviour, not for porting code.
- **Extension column.** `built-in`: core plumbing extensions build on.
  `built-in + extension point`: built in, and exposes a point extensions plug
  into. `plugin candidate`: could itself ship as a plugin on top of the
  extension points. Agents other than Claude, Codex, OpenCode, Gemini and the
  custom command are classed as plugin candidates (adapters).
